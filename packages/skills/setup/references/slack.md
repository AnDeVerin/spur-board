# Slack setup

Use this when the orchestrators or feed channel is not configured, or the app-level token is missing.

1. Check the bot's current channel membership. List the private channels it can see and ask the operator, one choice at a time, which should serve orchestrators and feed. An empty list does not prove no channels exist: the bot sees only private channels to which it was invited. Store channel IDs in config, never guessed names.
2. If no channel fits, ask for an operator-chosen prefix and suggest available names using it. The operator creates or invites the app to channels; ask before any app or channel change.
3. Check whether an app and slash command already exist. Before generating a manifest, have the operator confirm that the chosen slash command, app name and channel names are free in the workspace: no other app or Board uses them, or commands and delivery can reach the wrong Board. The bot token cannot list other apps' slash commands, so do not claim an automatic check; ask the operator to type the command in a Slack message box and look at the autocomplete list, and to look at the workspace's installed apps. If a name is taken, suggest names with an operator-chosen prefix, such as `/acme-board`, `acme-board`, `#acme-orchestrators` and `#acme-board-feed`. If the app or command is missing, use `board slack manifest --app-name <name> --command <slash-command>` to prepare a manifest with operator-chosen names. The operator creates the Slack app; do not claim the manifest creates it. Set `slack.appName` and `slack.command` in config to the selected names.
4. The manifest cannot create the app-level token with `connections:write`. In the Slack app settings, open **Basic Information → App-Level Tokens** and create a token with that scope. Then use the private entry procedure in [secret files](secrets.md). Never ask for a token value in chat.
5. Check channel membership and command configuration with online doctor. If a check fails, apply its reported fix after inspecting state.
